# FastPassword 使用说明

> 记住一个记忆密码，为每个站点生成互不相同的高强度密码。
> **不存站点密码、不联网、无后门**——密码是算出来的，不是存起来的。

---

## 1. 工作原理（30 秒版）

```
记忆密码  +  区分代号  +  账号（可空）  +  参数（长度 / 字符集）
        │
        ▼  Argon2id 派生（64 MiB 内存 × 3 轮）
        │
   该站点专属密码
```

- **同样的输入，永远得到同样的密码**——在任何电脑、任何时间重算都一致。
- **任何一项变了，密码就完全不同**——记忆密码、代号、账号、长度、字符集，改一个字都算换了一把新钥匙。
- 账号**可以留空**，但空账号也是算法的一部分：留空算出来的和填了账号算出来的，是两个不同的密码。
- 程序**不保存生成的密码**，也没有任何网络请求。它只保存两样东西：
  - 你的**开关设置**（明文的 `settings.json`，里面没有秘密）；
  - 你登记的**账号清单**（名称 + 账号 + 代号 + 参数 + 备注，存在加密的 `fastpassword.db` 里，没有密码打不开）；
  - 一份**用备份密钥加密的记忆密码**，专门用来应付"忘了密码"这一种情况。

## 2. 快速上手

**第一次启动**

| 步骤 | 操作 |
|---|---|
| ① | 程序会请你**设置记忆密码**——输两遍。它就是你的主密码，也是以后每次进入程序的钥匙 |
| ② | 紧接着弹出**备份密钥**：一串 8 组的字符，**只显示这一次**。抄到纸上或存进密码管理器，然后点「我已抄下，继续」 |
| ③ | 进入后正常使用：填代号 → 自动出密码 → 复制 |

**以后每次启动**

| 步骤 | 操作 |
|---|---|
| ① | 输入**记忆密码**解锁（约 0.3 秒） |
| ② | 点左下角 **新增** 录入一条（名称、账号、代号、长度、字符集、备注）；或者直接在右侧空白表单里填代号算一个临时密码 |
| ③ | 左侧点一条记录 → 右侧立刻显示密码 → 点 **复制** 去粘贴 |

不想登记也能用：不点新增、不留记录，就是一个纯推导工具，和以前完全一样。

## 3. 主窗口

解锁后是左右两栏。

**左栏：账号清单**

| 区域 | 说明 |
|---|---|
| 搜索框 | 按名称 / 账号 / 代号 / 备注模糊过滤，不区分大小写 |
| 清单 | 第一条是**名称**，第二条是**账号**。点一条就把全部字段填回右栏并立刻重算密码 |
| 新增 | 弹出录入窗口，填完保存即入库（同「代号 + 账号」会先问你要不要覆盖——覆盖会带上新的长度/字符集） |
| 删除所选 | 删掉当前选中的记录（会弹窗确认；只删记录，不影响任何已生成的密码） |

**右栏：当前站点**

| 区域 | 说明 |
|---|---|
| 名称 | 这条记录的标签，例如「GitHub 工作账号」。**不参与计算**，只影响显示与搜索 |
| 账号 | 登录名或邮箱，**参与派生**：同一代号下不同账号会得到不同密码（见第 9 节第一条） |
| 区分代号 | 站点标识，参与派生。随便起但要能记住，建议直接用域名。**不填不出密码** |
| 长度 | 12 / 16 / 20 / 24 / 32，默认 16 |
| 字符集 | **字母数字**（默认，绝大多数站点可用）/ **字母数字符号**（站点要求特殊符号时选它） |
| 生成密码 | 立即生成（跳过 0.5 秒等待）。浏览态也能点，等于重算一次 |
| 修改 / 保存 / 取消 | 压在最底部右下角。见下面的「浏览态与修改」 |
| 密码卡片 | 默认显示掩码圆点，点 👁 切换明文；点 ⧉ 复制 |
| 备注 | 可选，例如「工作邮箱，二次验证在手机」。存进清单，不参与计算 |

**标题栏**

| 位置 | 说明 |
|---|---|
| 左上 `FastPassword v1.1.0` | **点版本号**弹出「版本信息」：程序版本、算法版本、.NET 运行时、系统、架构、数据目录，可一键复制成文本 |
| 右上 ❗ / 🔒 / ⚙ | 使用要点 / 锁定 / 设置。**锁定态只显示 ❗**，锁定与设置都要解除锁定后才出现（减少解锁前可被误触的入口）。第一次使用（还没设记忆密码）时会自动弹一次「使用须知」，之后点感叹号随时回看 |

**浏览态与修改**

点左侧任意一条记录后，右栏所有输入框**置灰不可改**——避免手一滑就把某条记录的代号改了、下次算出别的密码。
窗口最底部右侧这时出现两颗按钮（「修改」带强调色）：

| 状态 | 右下角按钮 | 行为 |
|---|---|---|
| 浏览态（刚点开记录） | **修改** + **取消** | 修改：解锁表单进入编辑；取消：取消选中，回到空白可自由计算的状态 |
| 编辑态（点过修改） | **保存** + **取消** | 保存：写回清单并回到浏览态；取消：丢掉改了一半的内容，回到浏览态 |

快捷键：**Esc** 逐层退出（编辑态 → 浏览态 → 空白）；锁定页按 **Esc** 清空输入；设置窗口 / 录入窗口里 **Esc** 等于取消。

选中某条记录后，**Ctrl+C** 复制它的密码、**Ctrl+B** 复制它的账号。
这两个键**只在本程序窗口有焦点时生效**，不注册全局热键；光标在输入框里时它们仍是普通的文本编辑操作
（可在设置里整体关掉）。

## 4. 强度条怎么看

设置记忆密码或解锁时，输入框内部有一条彩色填充，
颜色代表强弱，**填满整个输入框 = 很强**：

| 填充颜色 | 含义 |
|---|---|
| 红 | 太弱，几秒就能被暴力破解，请加长 |
| 橙 | 偏弱，建议 12 个字符以上 |
| 琥珀 | 一般，可用，再加长更稳 |
| 绿 | 强，配合本程序的派生算法足够安全 |
| 深绿（填满整框） | 很强 |

没有文字提示——颜色和填充长度就是全部信号。常见坏密码（`123456`、`password`、`qwerty` 等）会被直接判红。

## 5. 复制与剪贴板

- **密码从一开始就不进 Win+V 历史**：复制时用 `ClipboardContentOptions.IsAllowedInHistory = false` 写入，
  系统的历史服务会直接跳过这条内容——不是"先记下来再删掉"，而是压根没有落进去。
  同一机制也禁止了跨设备漫游（`IsRoamable = false`）。
- 点复制后，密码卡片背景出现一条**倒计时条**，从右往左缩短——它走完，剪贴板里的密码就被清掉。
- 清除时间在设置里选：**10 / 15 / 30 秒**（默认 30 秒）。这是第二道防线：剪贴板在位期间任何程序都能读，
  清得越早暴露窗口越小。
- 复制**账号**不套这个限制——账号不是秘密，正常进历史，方便连续粘贴。
- 中途你复制了别的内容，倒计时到了也不会误删你新复制的东西。
- **退出程序时也会清**：还没走完的倒计时会在退出流程里补上（先清干净再关窗），所以密码不会因为"关得太快"留在剪贴板里。
- 把清除时间改成「不清除」时，**已经在跑的倒计时会立刻停掉**——不会"明明选了不清除，到点还是被清了"。

| 设置项 | 默认 | 说明 |
|---|---|---|
| 复制后自动清除剪贴板 | 30 秒 | 不清除 / 10 / 15 / 30 秒四档，配合卡片上的倒计时条。密码本来就不进 Win+V 历史，这一项只决定剪贴板本身留多久 |
| 启用快捷键 | 开 | 窗口内 **Ctrl+C** 复制所选条目的密码、**Ctrl+B** 复制账号。不注册全局热键；光标在输入框里时让位给文本编辑 |
| 隐藏 10 秒后自动锁定 | 开 | 收进托盘 10 秒后就要重新输记忆密码，离开电脑也安全 |
| 防截屏 | 开 | 开启后**任何截图 / 录屏都截不到本程序的窗口**（含设置窗与新增窗，包括你自己用 Win+Shift+S） |
| 失焦自动隐藏 | 关 | 点到别的窗口就自动收进托盘 |
| 关闭按钮收进托盘 | 开 | 点 ✕ 不退出，收进托盘 |
| 外观 | 跟随系统 | 浅色 / 深色 / 跟随系统，下拉即时预览，点保存生效 |

**所有数据都在程序目录下的 `data\` 里**，用户目录（`%LOCALAPPDATA%`）不写任何东西：

```
FastPassword\
├─ FastPassword.exe
└─ data\
   ├─ fastpassword.db       加密的账号清单（含校验段与备份密钥段）
   ├─ settings.json         开关与时长（明文，里面没有秘密）
   ├─ selfcheck.json        启动自检的基线缓存
   └─ logs\app.log          运行日志（不含密码与记录内容）
```

| 文件 | 说明 |
|---|---|
| `fastpassword.db` | **逐行 AES-256-GCM**，没有记忆密码（或备份密钥）打不开 |
| `fastpassword.db-wal`、`-shm` | SQLite 的临时文件，**只在解锁期间存在**，正常退出会合并回主库并消失 |
| `settings.json` | 明文配置，可整份拷；删了会恢复默认值 |
| `logs\app.log` | 明文日志，可随时删 |

因为整套东西都在程序文件夹里，**这个文件夹就是一份完整实例**：拷到 U 盘或另一台电脑，双击就能用，
不需要安装、不写注册表、不动用户目录。升级时把新的程序文件覆盖进同一个文件夹即可，`data\` 原样保留。

> ⚠️ **程序必须放在有写权限的位置**。解压到 `C://Program Files` 下会因无写权限无法建库，
> 建议放 `D://FastPassword`、桌面或用户文档。
>
> 换电脑时连 `data\` 一起拷走，启动后输原来的记忆密码即可——数据库不绑定机器，密钥只由记忆密码派生。

## 8. 安全设计

- **站点密码零存储**：生成的密码从不落盘，也不出现在任何日志里；锁定时，密钥材料（`byte[]` 形式的那两把）会被清零。
  记忆密码本身是 .NET `string`（运行时无法保证擦除），见下面「诚实的边界」第 1 条。
- **数据库里没有明文业务数据**：`fastpassword.db` 的 `accounts` 表每行只有「随机 GUID + 12 字节 nonce + 密文」；`meta` 表只有公开的 KDF 盐与两段密文。实测对整个文件 `grep` 站点名、账号、备注，一个字都搜不到。
- **逐行认证**：每条记录用 AES-256-GCM 单独加密，AAD 绑定了这条记录自己的 id——把 A 行的密文搬到 B 行会直接解不开，而不是"显示成别人的账号"。
- **锁定有速度代价**：解锁本身就是一次 Argon2id（约 180 ms），拿这个文件离线爆破记忆密码，和爆破你任意一个站点密码一样难。
- **SQLite 的边角也关掉了**：`temp_store=MEMORY`（中间结果不写临时文件）、WAL 模式（写入不重写整库，崩溃可回滚）、`PRAGMA user_version` 防降级。WAL 与 journal 里落的同样只有密文，明文从不经过数据库引擎。
- **抗爆破**：派生用 Argon2id（64 MiB 内存 × 3 轮），批量离线猜测的代价极高。
- **防截屏**：窗口对截图 / 录屏 / 远程投影隐身（Win10 2004+；老系统退化为"截到黑块"）。
- **启动自检**：每次启动验证派生算法与冻结基线一致，不一致才弹窗（阻断级）；
  归一化指纹（依赖系统 ICU，Windows 更新后变化属正常）只**提示一次**，不阻断使用，并记入本地日志。
- **本地日志**：`data\logs\app.log`，只记错误类型、耗时与指纹，**不记任何输入**。
- **参数即身份**：长度和字符集参与派生，这保证了"改参数 = 全部换新密码"，也意味着下面第 9 节的提醒。

**诚实的四条边界**

1. 记忆密码在解锁期间是一个 .NET `string`（无法保证清零），内存被高权限进程读取这件事本程序管不了。
2. 为了让备份密钥能"找回记忆密码"，程序会**用备份密钥加密保存一份记忆密码**（存在 `meta` 表里）。它不是明文，也没有备份密钥就打不开；但它确实在磁盘上了——这是"可恢复"必然要付的代价。BitLocker 的体积加密密钥也是这么存的。
3. 备份密钥本身**不落盘**，只在生成时显示一次。丢了它就只剩记忆密码这一条路。
4. 本地程序无法防"把整个数据库回滚成旧备份"：如果你今天删了一条记录，攻击者把昨天的备份覆盖回来，程序分辨不出来。

## 9. 常见问题

**Q：账号参与计算吗？**
参与（算法 v2.1）。账号会进 salt，所以同一代号下 `work@example.com` 和 `me@example.com` 拿到的是两个不同的密码；
**留空与填了账号也是两个不同的密码**。

**Q：以前的密码还能用吗？**
v2.1 是破坏性的算法变更（账号段无条件进 salt），v2.0 时期的任何密码都算不出来了。
本项目此前没有实际部署，所以这次直接切换；此后 salt 的字节布局不再变动，现有密码会一直稳定。

**Q：为什么没输代号就不生成密码？**
代号是用来区分站点的，没有它派生出的密码无法绑定任何站点。这是刻意设计。

**Q：改了长度或字符集，同一个站点的密码怎么全变了？**
参数参与派生，这是刻意的。改完参数后，**老站点要用老参数重新生成**，或者去站点上重置密码。平时别随意改全局参数——清单里每条记录自带参数快照，就是为了避免这个坑。

**Q：记忆密码忘了怎么办？**
用**备份密钥**找回来。解锁页点「忘记记忆密码？」→ 输入首次设置时那串 8 组密钥 → 程序解出你的记忆密码并直接解锁，同时把密码显示给你（这一步只显示一次，请马上记下来）。
备份密钥也丢了，就真的没有办法了——只能清空重来，所有站点密码都需要重新设置。

**Q：备份密钥是什么？安全吗？**
首次设置记忆密码后，程序会生成一串 32 位密钥（8 组 × 4 位，像 `XXXX-XXXX-…`），**只显示这一次**。
它是 160 位随机数，用 Crockford Base32 编码——字母表里没有 `I L O U`，输入时 `O` 会被当成 `0`、`I/L` 当成 `1`，照纸条打错一点的常见情况能自动纠正。
它不参与站点密码推导，只用来解开"被加密保存的那份记忆密码"。抄在纸上是最稳的做法，别放进网盘或邮件。
已经解锁时，可以在设置里 **重新生成**（旧密钥立即作废）。

**Q：账号清单丢了 / 换电脑了怎么办？**
清单只是便利贴，密码不依赖它。在新电脑上重新设置记忆密码（设成同一个），所有密码照样能算出来；把整个 `data\` 目录拷过去则连清单一起恢复（到新机器仍要用同一个记忆密码打开）。

**Q：忘记某个站点的密码了？**
只要记忆密码、代号、参数和当初一致，重新生成出来的就是同一个密码。清单里存着当初的参数，点一下就对。

**Q：换电脑 / 重装系统怎么办？**
装好本程序，用同样的记忆密码和代号，所有密码都能原样重算出来。没有任何数据必须迁移。
想把账号清单也带过去：把旧机器上的整个 `data\` 目录拷到新机器程序目录下即可——程序的所有数据都在这一个文件夹里。

**Q：为什么截图截不到这个窗口？**
"防截屏"默认开启，主窗、设置窗、新增窗都会应用。需要截图演示时，先到设置里暂时关掉它。

**Q：复制后 Win+V 里还能看到密码？**
正常情况下**看不到**：写入时就带上了"不允许进入历史"的标记，Win+V 里不会有这条。
如果你在历史里确实看到了，说明当前系统缺少 `ClipboardContentOptions`（1809 之前），
程序会退回普通写入并尝试事后删除——那时窗口需要在前台，否则请在历史里手动删除。

**Q：弱密码怎么没有文字提醒？**
设置密码/解锁时，输入框内的强度条就是提醒（颜色 + 填充长度），没有重复的文字。

**Q：界面上的提示去哪了？**
主界面不再有常驻提示文字。只有**真出事**才会弹一个「提示」对话框：解锁密码不对（直接显示在解锁页）、
账号清单写盘失败、启动自检发现算法漂移、复制到剪贴板失败、热键被别的程序占用、少量记录校验失败被跳过。
正常使用全程无弹窗。删除记录、覆盖已有「代号 + 账号」这类不可撤销操作会走独立的「请确认」对话框。

## 10. 分享给别人用

程序是**绿色免安装**的，分发 zip 即可。有两个包可选：

| 包 | 体积 | 内容 | 适用 |
|---|---|---|---|
| `FastPassword-v1.1.0-win-x64.zip`（**自包含版**） | 约 64 MB | 一个 `FastPassword` 文件夹，顶层 290 项 | **默认选它**。运行时全部随包，对方什么都不用装 |
| `FastPassword-v1.1.0-win-x64-lite.zip`（精简版） | 约 11 MB | 一个 `FastPassword-lite` 文件夹，45 项 | 对方已装好 .NET 10 Desktop Runtime 和 Windows App Runtime 2.5.x（均为 x64），少一样都起不来 |

两个包里都带 `使用说明.md`，解压后各自只有**一层**顶层文件夹，不会把几百个文件撒到你选的目录里。

> 自包含版里的文件看着多（约 290 项），是 .NET 与 Windows App SDK 的运行时——**.NET 规定程序集必须和 exe 同级**，
> 不能塞进子目录，否则启动就找不到依赖。所以能做的整理只有两件，打包时已经做了：
> 删掉调试符号 `.pdb`，以及裁掉 WinUI 自带的 60 多个语言资源目录（只留 `zh-CN`），
> 顶层文件夹从 88 个降到 3 个（`Assets`、`Microsoft.UI.Xaml`、`zh-CN`）。

**安装步骤**（两个包相同）：解压到**有写权限**的位置（不要放 `Program Files`）→ 进入 `FastPassword` 文件夹 → 双击 `FastPassword.exe`（可右键发送到桌面快捷方式）。不需要管理员权限，不写注册表。系统要求：Windows 10 1809 或更新版本，64 位。

配置（外观、时长等开关）与账号清单都存在每个程序文件夹各自的 `data\` 里，互不影响；密码不依赖任何配置——对方记住自己的主密码和代号，在任何一台电脑上都能重算出同样的密码。`data\fastpassword.db` 是加密的，想带清单换电脑就把整个 `data\` 目录拷走（连同 `-wal`/`-shm`，或先退出程序）。

**自己重新打包**（改了代码之后）：双击项目根目录的 `打包.bat`，一次生成两个 zip 到 `dist\`。版本号在 `Directory.Build.props` 的 `<Version>` 里改，记得同步改 bat 里的 zip 文件名。

> **为什么没有 AI/机器学习组件**：早期版本引用了 `Microsoft.WindowsAppSDK` 聚合包，它会把整个
> Windows AI/ML 栈拖进依赖图——`onnxruntime.dll` 20 MB + `DirectML.dll` 18 MB，
> 合计约 40 MB 的本程序一个字节都用不到。现在改引组件包
> （`Microsoft.WindowsAppSDK.WinUI` + `Microsoft.WindowsAppSDK.Runtime`），
> 这 40 MB 从源头上就没了，**不再需要打包时手工删除**。
>
> **不做单文件版**：WinUI 3 的单文件发布需要把 Windows App SDK 运行时一起内嵌（否则
> `resources.pri` 找不到，启动即抛 `XamlParseException`），做出来的 exe 约 70 MB，
> 和自包含文件夹版体积相当，却失去可调试的符号文件，排障更麻烦。**分发文件夹版即可。**
> 再小只能走 Native AOT，但 WinUI 3 的反射式 XAML 与 AOT 兼容性差，属于另一个量级的改造。

## 11. 三条最重要的话

1. **记忆密码忘了 = 所有密码全部作废**，没有任何找回手段。首次设置时请输两遍、想清楚。
2. **改长度 / 字符集 = 同一代号换一把新钥匙**，老站点要按老参数重算或重置密码。清单里每条记录自带参数快照就是为了防这个。
3. 程序替你记住的只有规则和一张加密的便利贴，真正要保管好的只有你的记忆密码。
