# 核心算法稳定性保证

> 目标：**在任何情况下输出相同的密码。**
> 更精确的表述：**要么输出逐字节相同的密码，要么明确拒绝并报错——绝不允许静默算出不同的结果。**
> 日期：2026-10-18 ｜ 状态：已实测验证，非推理

---

## 0. 核心原则

**静默失败比崩溃危险一万倍。**

用户不会察觉"密码晚了一周开始不对"。等他发现时，可能已经被锁在十几个账号外面。
所以本项目的稳定性策略是：

| 情况 | 正确行为 | 错误行为 |
|---|---|---|
| 输入合法、环境正常 | 输出确定密码 | — |
| 输入非法（孤立代理项、U+FFFE） | **抛异常 / 明确报错** | 替换成 U+FFFD 继续算 ❌ |
| 环境漂移（ICU/库版本变了） | **启动自检报警** | 静默算出不同密码 ❌ |
| 参数与上次不同 | 参数进 salt，输出必然不同（这是设计） | 复用旧参数导致密码对不上 ❌ |

## 2. 九类威胁与处置

| # | 威胁 | 后果 | 处置 | 状态 |
|---|---|---|---|---|
| T1 | 参数组合变化（长度/字符集/strict） | 同输入不同密码 | **全部进 salt 派生** | ✅ 已实现，曾出过后缀 bug |
| T2 | Argon2 库版本升级 | 静默改变输出 | 精确版本 + `packages.lock.json` + 回归向量 | ✅ 待 M0 落实 |
| T3 | Argon2 版本号 v16/v19 | 输出不同 | 锁 v19；库不暴露则用回归向量锁定 | ✅ 已实测 |
| T4 | `p` 并行度 | 输出不同 | **锁 p=1**，代码里写成常量且不可配 | ✅ 已实测 |
| T5 | 内存单位误判（KiB vs 字节） | 参数错 64 倍 | 与 libargon2 交叉验证确认是 KiB | ✅ 已实测 |
| T6 | ICU/Unicode 数据版本差异 | 极少数新字符归一化不同 | **启动时指纹自检（只提示不阻断）**，差异记入本地日志 | ⚠️ 风险存在，有对策 |
| T7 | 孤立代理项 | 静默替换成 U+FFFD | **严格 UTF-8**；实测 ICU 的 `Normalize` 会先行拦截，编码层是第二道防线 | ✅ 已实测 |
| T8 | U+FFFE 等非字符 | `Normalize` 抛异常 → 崩溃 | 捕获 → 返回明确错误 | ✅ 已实测 |
| T9 | 区域性敏感 API | 土耳其语下 `I↔ı` 出错 | 全程 ordinal / invariant | ✅ 已实测 |

**T6 是唯一无法彻底消除的**：归一化依赖系统 ICU，不同 Windows 版本的 Unicode 数据可能对**极少数新增字符**给出不同结果。对策见 §5 环境自检。

## 3. 实现契约（12 条硬规则）

`FastPassword.Core` 里**每一条都不可违反**。违反任意一条，稳定性保证即失效。

### 3.1 归一化

```csharp
// ✅ 正确：NFC + 捕获异常
byte[] Encode(string s)
{
    string nfc;
    try { nfc = s.Normalize(NormalizationForm.FormC); }
    catch (ArgumentException) { throw new FpInputException("输入包含无法归一化的字符"); }
    return StrictUtf8.GetBytes(nfc);
}

// ❌ 错误：不归一化（同一视觉字符不同输入法算出不同密码）
Encoding.UTF8.GetBytes(s);

// ❌ 错误：先编码后归一化（编码后无法归一化）
```

**顺序必须固定：`NFC → UTF-8`。**

### 3.2 编码

```csharp
// ✅ 静态单例，严格模式
private static readonly UTF8Encoding StrictUtf8 = new(encoderShouldEmitUTF8Identifier: false, throwOnInvalidBytes: true);

// ❌ 错误：宽松模式，孤立代理项静默变 U+FFFD
Encoding.UTF8.GetBytes(s);
```

### 3.3 字节序

```csharp
// ✅ 显式小端
BinaryPrimitives.WriteInt32LittleEndian(buf, value);

// ❌ 错误：依赖平台字节序
BitConverter.GetBytes(value);
```

### 3.4 字符判定

```csharp
// ✅ 全部 ordinal
char.IsAsciiDigit(c)
char.IsAsciiLetterLower(c)
char.IsAsciiLetterUpper(c)
string.Equals(a, b, StringComparison.Ordinal)

// ❌ 错误：区域性敏感，tr-TR 下会崩
c.ToString().ToLower()
CultureInfo.CurrentCulture.CompareInfo.IndexOf(...)
string.Compare(a, b)   // 没用 ordinal
```

### 3.5 大整数

```csharp
// ✅ 显式无符号大端
new BigInteger(seed, isUnsigned: true, isBigEndian: true)

// ❌ 错误：默认有符号小端，负数/字节序全乱
new BigInteger(seed)
```

### 3.6 Argon2 参数（全部写死，不做配置）

```csharp
MemorySize = 65536,            // KiB
Iterations = 3,
DegreeOfParallelism = 1,       // 锁死，改则输出变
// version 必须 19（0x13）；若库不暴露，用回归向量锁定
// secret / associatedData 必须为 null / 空
// salt 32 字节，输出 32 字节
```

### 3.7 映射

```csharp
// ✅ BigInteger 连除，任意 base 无偏
// ❌ 禁止 byte % alphabet.Length（3% 量级偏差）
```

### 3.8 参数一致性

**任何影响输出的参数都必须进 salt。** 当前清单：

```
version_tag, site, length, charsetId, strict
```

新增参数（如未来的"排除易混淆字符"）**必须**同时进 salt，否则会与旧输出冲突。

### 3.9 空值与长度

| 输入 | 行为 |
|---|---|
| 空主密码 `""` | **拒绝**（等于公开密码） |
| 空站点 `""` | 允许（salt 结构完整，已验证） |
| 主密码 1 字符 | 拒绝（策略层，见 §4） |
| 主密码 > 1024 字符 | 拒绝（防滥用，Argon2 处理超长 key 会线性变慢） |
| 站点 > 256 字符 | 拒绝 |
| 长度参数 | 12–32，其他拒绝 |

### 3.10 不 trim、不 normalize 之外的处理

**不做任何隐式修正**：不 trim 空格、不折叠连续空格、不转换全角半角。

理由：隐式修正会在"用户以为输入了 A、程序用了 B"之间制造不可见的鸿沟。宁可让用户看到"检测到首尾空格"的警告，也不要偷偷改掉。

### 3.11 内存

```csharp
finally { CryptographicOperations.ZeroMemory(masterKey); CryptographicOperations.ZeroMemory(raw); }
```

`string` 无法清零，这是已知局限。但字节数组必须清。

### 3.12 依赖版本

```xml
<PackageReference Include="Konscious.Security.Cryptography.Argon2" Version="1.3.1" />
```
**精确版本号，不用 `[1.3.1,)` 这类范围。** 且必须生成并提交 `packages.lock.json`。

## 4. 三层防线

### 第一层：输入校验（在进入算法前拦截）

```csharp
InputValidation.Validate(master, site, p) =>
    - 长度范围
    - 是否含孤立代理项（严格 UTF-8 会抛，提前给出友好文案）
    - 是否含 U+FFFE/FFFF 等归一化异常码点
    - 是否含控制字符 / 零宽字符 → 警告（不阻断）
    - 首尾空白 → 警告（不 trim）
```

**一律"拒绝 + 明确原因"，不"修正后继续"。**

### 第二层：回归向量（编译期就固化）

`FastPassword.Core.Tests` 里跑 §7 的 17 个向量。任何实现漂移（换库、改代码、升级运行时）都会立刻爆红。

**这些向量是代码的一部分，不是文档装饰。** 改动任何一个都需要显式的破坏性变更评审。

### 第三层：启动自检（环境漂移检测）

应用启动时异步执行（不阻塞 UI），首次约 400 ms，之后约 180 ms：

1. **Argon2 自检**：用固定 master/site 算一个内置向量，比对固化值。**不通过 = 阻断**（弹窗，建议不要用它生成新密码）。
2. **归一化指纹自检**：BMP 全扫描算 SHA-256，比对基线 `4d567449...`。**不通过 = 仅提示**。

阻断与提示分开的原因：指纹只受「主密码/代号里含非 ASCII 组合字符」的用户影响，
而它随系统 ICU 更新变化是**正常现象**。把正常的环境更替算成"算法漂移"，结果是每次
Windows 更新都给所有人弹一次恐怖弹窗——告警一旦变成噪音就再也没人看。

指纹结果与运行环境指纹（运行时 + OS 版本）一起缓存在 `%LOCALAPPDATA%\FastPassword\selfcheck.json` 里：

- 环境未变 → **跳过全量扫描**（省掉那 200 ms），只跑 Argon2；
- 环境变了 → 重算一次；若指纹与上次不同，**只提示一次**，然后把它记成这台机器的新基线。

**两项结果都记入本地日志**（`logs\app.log`，只记错误类型、耗时与指纹哈希，不记任何输入）。

## 6. 做不到的事（必须写进关于页）

| 做不到 | 原因 |
|---|---|
| 保证跨 **所有** Unicode 版本绝对一致 | 归一化依赖系统 ICU；新增字符的归一化规则可能变化。缓解：指纹自检 + 只依赖 NFC 幂等性 |
| 保证 `string` 驻留内存被清零 | .NET 托管字符串不可控；只能清 `byte[]` |
| 抵御拿到盐后的定向爆破 | 确定性 salt 的固有代价；靠 Argon2 工作因子拉高成本 |
| 在没有 .NET 的机器上运行 | framework-dependent 需要装 Runtime；或用 self-contained（体积 ~150 MB） |
| 恢复错误的参数组合 | 参数即状态，丢了参数就丢了密码。**这是设计的必然代价** |

## 8. 复现验证的方法

```bash
# 跨实现（C# vs libargon2）
python _probe_stability/verify_v2.py

# 跨运行时（net8 vs net10），输出应除第一行外完全一致
cd _probe_multitfm
dotnet build -c Release
dotnet run -c Release -f net8.0  --no-build > out8.txt
dotnet run -c Release -f net10.0 --no-build > out10.txt
diff out8.txt out10.txt
```

两个脚本都是纯计算、秒级、零外部依赖（除 pip 装过一次 argon2-cffi）。改任何算法代码后跑一遍，就知道有没有破坏兼容性。
